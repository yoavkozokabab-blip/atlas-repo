# Phase 177 — Demo Repository Audit

**Date:** 2026-06-06  
**Method:** Live scan + plan generation across all demo packs, all standard prompts  
**No code changes. Findings only.**

---

## Executive Finding

The onboarding flow calls `loadDemoMode("small")`. The small demo produces **zero matched files** on every standard first-use prompt. This is a P0 blocker. Every user who clicks "Load Sample Repository" for the first time sees a plan with `## Files (top 5): - (none)`.

The medium demo produces the right output. The fix is one word.

## Impact Analysis Quality by Demo

### Medium demo — `api/handlers.py`

**Direct impact produced:**
```
- ui/dashboard.py
- function:api/handlers.py    ← RAW NODE ID LEAKING
- function:ui/dashboard.py    ← RAW NODE ID LEAKING
- list_routes                 ← BARE FUNCTION NAME, NOT A FILE
```

**P0 issue:** `function:api/handlers.py` and `function:ui/dashboard.py` are internal graph node IDs where the type prefix (`function:`) was not stripped before display. `list_routes` is a function name appearing as a "file path." These are not file paths. A developer reading this will be confused about what they're looking at.

This affects every impact analysis result. The internal node type prefix leaks into both the minimal export and the full export.

## Investigation Quality by Demo

### Medium demo — "requests are timing out"

The investigation returns:
```
Symptom: Reported: "requests are timing out". Likely area: api/routes.py.
```

**Issue:** `Reported: "..."` is an internal planning engine label. The user said "requests are timing out." Atlas prefixes it with "Reported: " and appends " Likely area: api/routes.py." to the symptom field. The user's own words are returned to them with engineering labels attached. This reads as machine output, not developer advice.

**Root cause label:**
```
Insufficient evidence. Atlas did not find enough repository evidence for a strong root cause 
(best evidence score 36/100, threshold 50). Provide a stack trace, error message, or exact 
file path and re-run.
```

This is the full internal error message including the numeric threshold (50) and score (36/100). A developer reading this learns two things: (1) Atlas doesn't know, and (2) Atlas uses numeric thresholds. Neither is what they wanted to hear, and the second is irrelevant internal detail.
