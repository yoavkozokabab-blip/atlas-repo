# Phase 102 — Architectural Risk Ranking Engine

**Status:** Implemented and verified.
**Date:** 2026-06-01
**Goal:** Replace prose-only bottleneck fan-in heuristics with a deterministic,
structured **Architectural Risk Ranking Engine** over the Phase 100G production
dependency graph, exposed on the existing bottleneck / architectural-risk ask
route without changing dependency, impact, or retrieval behavior.

---

## 1. Architecture

```
ask.answer()
  └─ question_understanding (101A) → category bottleneck
       └─ _answer_bottlenecks()
            ├─ depgraph.build_graph(scope=production)   # 100G
            └─ architectural_risk.rank_modules()        # 102
                 └─ architectural_risk_ranking (structured)
                 └─ answer / evidence (formatted breakdown)
```

**New module:** `builder_core/architectural_risk.py` (`engine_version`: `phase102-v1`,
`schema_version`: 1).

**Response field:** `architectural_risk_ranking` on every non-degraded bottleneck
answer (and attached on degraded graph paths for debugging).

---

## 2. Ranking signals and weights

Each production-scoped **module** node in the depgraph receives a weighted score.
Components are rounded to two decimals; `total_score` is their sum.

| Breakdown key | Source | Weight / rule |
|---|---|---|
| `fan_in` | Resolved `imports` edges (in-degree) | × 1.0 |
| `fan_out` | Resolved `imports` edges (out-degree) | × 0.35 |
| `import_cycle_member` | `statistics.import_cycles` | +5.0 if in any cycle |
| `component_root` | `statistics.largest_components[].root` | +3.0 |
| `module_size_loc` | Node / index line count | +1.0 per 500 LOC, cap 4.0 |
| `untested_module` | `risk._test_corpus` stem match | +3.0 if no test reference |
| `churn_hotspot` | `index.churn` | +0.5 per 5 commits, cap 3.0 |
| `contract_evidence` | `python_analysis` finding severities | high +2, medium +1, low +0.5 |
| `subsystem_import_hub` | Cross-subsystem import fan-in ≥ 2 | +2.0 |

Raw metrics (`fan_in`, `fan_out`, `line_count`, `has_test_reference`, etc.) are
also returned under each ranked row's `metrics` for clients that prefer counts over
weighted components.

**Scope:** Only `type == "module"` nodes from `depgraph.build_graph(..., scope="production")`.
Dataset trees and non-production roles remain excluded (100G).

## 3. Structured payload (schema)

```json
{
  "schema_version": 1,
  "engine_version": "phase102-v1",
  "graph_scope": "production",
  "scope_diagnostics": { "...": "..." },
  "degraded": false,
  "import_cycle_count": 4,
  "modules_considered": 673,
  "ranked_modules": [
    {
      "rank": 1,
      "module_id": "module:config.py",
      "path": "config.py",
      "label": "config",
      "subsystem": "(root)",
      "total_score": 220.65,
      "score_breakdown": { "fan_in": 212.0, "...": 0.0 },
      "signals": ["import fan-in=212", "..."],
      "metrics": { "fan_in": 212, "fan_out": 7, "...": true }
    }
  ]
}
```

Human prose is generated by `format_ranking_answer()` / `format_ranking_evidence()`
and no longer uses the retrieval fallback string for this intent.

## 7. Notes

- Cycle members can outrank high fan-in hubs on **total_score** (cycle weight 5.0);
  fan-in remains visible in `metrics` and `score_breakdown.fan_in`.
- Test presence uses corpus **reference** matching (same as risk module), not
  coverage percentages — coverage enters only when static analysis findings exist
  under `contract_evidence`.
