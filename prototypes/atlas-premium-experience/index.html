Answer

Authentication is split between the desktop account state, local API routes, and the workflow gate.

accounts_client.py owns persisted identity and local-mode state. accounts_routes.py exposes account and guest actions. server.py checks whether a signed-in or local-mode identity may run protected workflows. The browser UI starts local mode from atlas_accounts.js.

Why Atlas believes this

The cited functions form the complete path from UI action to persisted state to request-time workflow authorization. The account and billing endpoints remain separate from local repository workflows.

Caveat

The exact website authentication authority depends on the packaged app mode. This answer describes the desktop boundary and local-mode path.
